## 問題の生成

| ID | 決まり |
| --- | --- |
| G-01 | 問題は Web Worker の中で作る。完成した盤面からマスを抜いて作り、解が 1 つだけであることを、手筋だけで解けることで確かめる(手筋は正しい消去しかしないので、手筋だけで全部のマスが埋まり、数独のルールを満たす盤面は、解が 1 つだけになる)。解の数を数える処理(`countSolutions`)と難易度の判定(`judgeDifficulty`)は、作った問題をテスト(T-001 など)で確かめるのに使う(2026-11-03 のフェーズ 6 の網羅確認で、実装に合わせて直すとユーザが決めた) |
| G-02 | 乱数の元は引数で受け取る。同じ乱数の元なら、同じ問題になる(テストで確かめるため)。乱数の元は 0〜2^32-1 の整数(2026-11-03 にユーザが決めた) |
| G-03 | 決めた時間内に条件に合う問題を作れなかったときは失敗として返す。画面はエラーを表示し、もう一度試せるようにする。画面は、生成の時間の上限(`DEFAULT_TIME_LIMIT_MS`)に 5 秒を足した時間までに応答が無ければ、Worker を止めて失敗にする。Worker の `error` イベントも失敗にする(2026-11-03 にユーザが決めた)。応答を待っている要求が無いときの `error` イベントは、画面に知らせず、その Worker を捨てて次の要求で作り直す。Worker を起動できない(`new Worker` が例外を出す)とき、応答が読めない(`messageerror` イベント)ときも失敗にする(2026-11-03 のフェーズ 4 のレビューでユーザが決めた)。生成の時間の上限は 10 秒にする(2026-11-03 に、CPU を 6 倍遅くしてむずかしいの最大が 3.6 秒だった結果を見て、ユーザが決めた) |
| G-04 | Web Worker は、要求ごとに必ず 1 つの応答を返す。要求と応答には要求の番号(0 以上の整数)を付ける。失敗の理由は、時間切れ(`timeout`)、不正な要求(`invalid-request`)、そのほかのエラー(`error`)に分ける。不正な要求で番号も読めないときは、番号を `null` にする(2026-11-03 にユーザが決めた) |

## 難易度

手がかりの数と、解くのに必要な手筋で決める。推測(当てずっぽうで進めて戻ること)が必要な問題は、どの難易度でも出さない。

| ID | 難易度 | 手がかりの数 | 解くのに必要な手筋 |
| --- | --- | --- | --- |
| G-11 | かんたん | 38〜45 | シングル(naked single、hidden single)だけで解ける |
| G-12 | ふつう | 30〜37 | シングルに加えて、ロックされた候補、ペア(naked pair、hidden pair)のどれかが必要 |
| G-13 | むずかしい | 24〜29 | ふつうの手筋に加えて、トリプル(naked triple、hidden triple)か X-Wing のどれかが必要 |

手がかりの数は目安で、生成にかかる時間を測ってから調整する。変えたらこの表を直す。

手筋と判定の決まり(2026-11-03 にユーザが決めた):

| ID | 決まり |
| --- | --- |
| G-14 | ロックされた候補は、pointing(ブロックの中の候補が 1 つの行か列にそろう)と claiming(行か列の中の候補が 1 つのブロックにそろう)の両方。X-Wing は行どうしと列どうしの両方向。表に無い手筋(Swordfish など)は使わない |
| G-15 | 手筋は易しい順(シングル、ロックされた候補、ペア、トリプル、X-Wing)に試し、進んだらまたシングルから試す。使った手筋のうち一番難しいもので難易度を決める。手筋だけで埋めた盤面が数独のルールを満たさないときは、解けなかったものとする |
| G-16 | 手筋で決めた難易度と、手がかりの数の範囲の両方が合うときだけ、その難易度とする |
| G-17 | 問題を作るときは、手がかりの数の目標を範囲の中から乱数で決め、そこまでマスを抜く。抜くのは、解が 1 つのままで、手筋で解け、目当ての難易度より難しくならないマスだけ。目標まで抜いても目当ての難易度にならないときは、手がかりの数を変えずに「手がかりを 1 つ抜き、別のマスに解の数字を 1 つ足す」入れ替えを、決めた回数(今は 1,000 回)まで試す。残すのは、手筋で解け、目当ての難易度を超えず、今より易しくならない入れ替えだけ。目標の数まで抜けないとき、入れ替えても目当ての難易度にならないときは、新しい完成した盤面から作り直す。時間切れ(G-03)まで繰り返す(2026-11-03 のフェーズ 6 の網羅確認で、実装に合わせて書いた) |

## 入力

この章(数字の入力、メモ、元に戻す・やり直し)と、終わったゲームの操作(G-53)で「何も変わらない」操作は、受け取った状態をそのまま(同じオブジェクトで)返す。画面は、返ってきた状態が同じかどうかで保存を省く(2026-11-03 に、レビューの指摘を受けてユーザが書くと決めた)。

範囲外の数字(1〜9 以外)とマスの番号(0〜80 以外)を受け取った操作(数字の入力、消す、メモ)は、何も変えない(2026-11-03 のフェーズ 6 の網羅確認で、テスト仕様書の T-108 に合わせて書いた)。

### 数字の入力

入力の対象は、手がかりでも正解でもないマス(空欄か、誤りの数字が入ったマス)。

| ID | 操作 | 結果 |
| --- | --- | --- |
| G-21 | 正解の数字を入れる | マスに入り、そのマスのメモが消える(同じ行・列・ブロックのメモは G-33)。正解の入ったマスは変更も消去もできない |
| G-22 | 正解と違う数字を入れる | マスに入り、そのマスのメモが消える。間違いの回数が 1 増える |
| G-23 | 誤りの数字が入ったマスに、同じ数字をもう一度入れる | 何も変わらない。回数も増えない |
| G-24 | 誤りの数字が入ったマスに、別の数字を入れる | G-21 または G-22 と同じ |
| G-25 | 手がかりのマス、正解の入ったマスに数字を入れる | 何も変わらない |
| G-26 | 消す | 誤りの数字とメモを消す。回数は減らない。手がかりと正解のマスでは何も変わらない |
| G-27 | 入れ終わった数字を入れる | 9 か所すべてに正解が入った数字(手がかりを含む。誤りの数字は数えない)を、入れ終わった数字とする。画面は、入れ終わった数字のボタンとキーを、数字の状態でもメモの状態でも受け付けない。正解の入ったマスは変更も消去もできないので、入れ終わった数字でなくなるのは「元に戻す」(G-41)と「やり直す」(G-55)のときだけ(2026-11-04 にユーザが決めた。Issue #9) |

### メモ

| ID | 決まり |
| --- | --- |
| G-31 | メモの入力の状態で数字を入れると、空欄のマスのメモをその数字で付け外しする |
| G-32 | 数字の入ったマスにはメモを入れられない。メモは間違いの回数に数えない |
| G-33 | 正解の数字を入れると、同じ行・列・ブロックのマスのメモから、その数字を消す。誤りの数字を入れたときは消さない。消したメモは、その入力と 1 つの操作として履歴に残し、「元に戻す」1 回で入力と一緒に戻る(G-41)(2026-11-04 にユーザが決めた。Issue #7) |
| G-34 | 正解の数字を入れて、その数字が入れ終わった数字(G-27)になったときは、行・列・ブロックに限らず、すべてのマスのメモからその数字を消す(入れ終わった数字のメモは外せなくなるため)。G-33 と同じく、入力と 1 つの操作として履歴に残す(2026-11-04 の PR #15 のレビューの指摘で、ユーザが決めた) |

### 元に戻す・やり直し

| ID | 決まり |
| --- | --- |
| G-41 | 数字の入力、消す、メモの変更を、1 操作ずつ元に戻せる。何も変わらなかった操作は履歴に残さない |
| G-42 | 間違いの回数は、元に戻しても減らない。やり直しても増えない |
| G-43 | 元に戻した後に新しい操作をすると、やり直しの履歴を捨てる |
| G-44 | 元に戻した正解のマスは空欄に戻るので、もう一度入力できる |

## ゲームの終わり

| ID | 決まり |
| --- | --- |
| G-51 | すべてのマスが正解になったらクリア。タイマーを止め、成績に記録する |
| G-52 | 間違いが 3 回になったら失敗。タイマーを止め、成績に記録する |
| G-53 | 終わったゲームの盤面は操作できない。元に戻す、やり直しも使えない |
| G-54 | 成績の記録は、1 回のゲームで 1 度だけ。再読み込みしても重ねて記録しない。画面は、状態が「プレイ中」から「クリア」か「失敗」に変わったときだけ記録する。保存は、ゲームを先に、成績を後にする(成績の保存だけが失敗したときは、その 1 回が数え漏れる。二重には数えない)(2026-11-03 にユーザが決めた)。ゲームの保存に失敗したときは、成績を保存しない(保存したゲームが「プレイ中」のまま残り、再読み込みの後に遊び切ると二重に数えるため。その 1 回は数え漏れる。2026-11-03 のフェーズ 4 のレビューでユーザが決めた) |
| G-55 | 「やり直す」は同じ問題を初めの状態に戻す。入力、メモ、履歴、間違いの回数、タイマーをすべて初めに戻し、別のゲームとして数える |
| G-56 | 途中でやめたゲーム(新しいゲームで上書きしたもの)は、成績に数えない |

## 保存(localStorage)

| キー | 中身 |
| --- | --- |
| `sudoku:v1:game` | 最後のゲーム(1 つだけ)。全部の操作の後に保存する |
| `sudoku:v1:stats` | 成績 |

```ts
type Difficulty = "easy" | "normal" | "hard";
type GameStatus = "playing" | "cleared" | "failed";

// 盤面は 81 要素の配列。行ごとに左上から右下へ並べる。数字は 1〜9、空欄は 0
type Grid = number[];

interface CellSnapshot {
  index: number; // 0〜80
  value: number;
  notes: number[]; // 昇順
}

// 1 つの操作で変わったマスすべて(G-33 では、入力したマスと、メモを消したマス)
interface HistoryEntry {
  before: CellSnapshot[];
  after: CellSnapshot[];
}

interface SavedGame {
  difficulty: Difficulty;
  puzzle: Grid; // 手がかり
  solution: Grid;
  values: Grid; // 手がかりと入力
  notes: number[][]; // マスごとのメモ
  mistakes: number; // 0〜3
  elapsedSeconds: number;
  status: GameStatus;
  undoStack: HistoryEntry[];
  redoStack: HistoryEntry[];
}

interface DifficultyStats {
  cleared: number;
  failed: number;
  bestSeconds: number | null;
}

type SavedStats = Record<Difficulty, DifficultyStats>;
```

コードでは、プレイ中の状態も `SavedGame` と同じ形で持ち、`GameState` と呼ぶ(`src/lib/game/types.ts`)。

| ID | 決まり |
| --- | --- |
| G-81 | 読み込むときに形と中身を検証する。壊れた値、形の違う値、中身の食い違う値は捨て、ゲームなし・成績なしとして動く。例外で画面を止めない。確かめる中身は下の「読み込みの検証」 |
| G-82 | 保存できない(容量の超過、無効にされている、`localStorage` を参照するだけで例外が出る、など)ときも遊び続けられる。そのページを開いている間はメモリの状態で動き、画面に保存できないことを知らせる |
| G-83 | サーバーの描画では `localStorage` を読まない。ブラウザで読むまでの間は読み込み中の表示にして、hydration の不一致を起こさない |
| G-84 | 同じブラウザの複数のタブで同時に遊ぶことは想定しない。成績はページを開いたときに 1 度だけ読むので、別のタブで記録した成績は、後から保存したタブの値で上書きされて失われることがある(2026-11-03 のフェーズ 4 のレビューでユーザが決めた) |

### 読み込みの検証(G-81)

形と値の範囲に加えて、中身の食い違いも確かめる(2026-11-03 にユーザが決めた)。どれかに合わなければ、ゲームなし(成績は成績なし)にする。上の型に無い項目は捨てる。捨てた値は `localStorage` から消さない(次の保存で上書きされる)。整数の上限は、安全な整数(2^53-1)まで。

| 対象 | 確かめること |
| --- | --- |
| `difficulty`、`status` | 決めた値のどれか |
| `puzzle`、`values` | 81 要素で、どれも 0〜9 の整数 |
| `solution` | 81 要素で、どれも 1〜9 の整数。数独のルール(行・列・ブロックに重なりが無い)を満たす |
| 手がかりと解 | `puzzle` の 0 でないマスは、`solution` と同じ数字 |
| 手がかりと入力 | `puzzle` の 0 でないマスは、`values` でも同じ数字 |
| `notes` | 81 要素で、どれも 1〜9 の整数の、重なりの無い昇順の配列。メモがあるのは `values` が 0 のマスだけ |
| `mistakes` | 0〜3 の整数 |
| `elapsedSeconds` | 0 以上の整数 |
| 状態と中身 | `failed` は `mistakes` が 3 で、`values` が `solution` と同じでない(失敗した誤りのマスが残るため)。`cleared` は `mistakes` が 3 未満(3 回目の間違いで失敗になるため)で、`values` が `solution` と同じ。`playing` は `mistakes` が 3 未満で、`values` が `solution` と同じでない |
| `undoStack`、`redoStack` | 配列で、各要素の `before` と `after` は `CellSnapshot` の配列。`index` は 0〜80 の整数で、`puzzle` の手がかりのマスではない。`value` は 0〜9 の整数、`notes` は上と同じ形で、`value` が 0 でなければ空(2026-11-03 にユーザが足すと決めた。手がかりのマスを指す履歴で元に戻すと、手がかりが書き換わり、そのゲームが先に進めなくなるため) |
| 成績 | 3 つの難易度のそれぞれに、`cleared` と `failed` が 0 以上の整数、`bestSeconds` が `null` か 0 以上の整数。`bestSeconds` があるのは `cleared` が 1 以上のときだけで、そのときは必ずある |
